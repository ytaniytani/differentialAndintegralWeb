ライティング&レンダリングで体感する微分・積分

トーンカーブも、ノーマルマップも、ブルームも、フォグも——中身はぜんぶ「傾き」と「足し算」。

必要な数学は中学まで。あとはこのページの中で全部つくります
遊び方 P1 傾き P2 面積 §1 トーンカーブ §2 法線 §3 エッジ §4 ブルーム §5 影 §6 フォグ §7 時間 まとめ

§0 このページの遊び方

このページは読むより触るページです。スライダーを動かすと、グラフと絵がリアルタイムに変わります。 先に結論だけ言ってしまうと——

微分とは「傾き(変化の速さ)を取り出す道具」。
積分とは「細かく刻んで足し合わせる道具」。
それだけです。あなたが今日調整したトーンカーブもブルームもフォグも、中身はこの2つで出来ています。 上のヘッダーで動いている陰影も、実は「地形の傾き(微分)」から計算しています。

準備編 — 中学数学から橋を架ける
★1 やさしい

P1 傾き=変化の速さ — ライトのフェードイン

つかう数学: 一次関数 y = ax + b の傾き(中2) / 負の数(中1)

照明卓のフェーダーを上げてライトをフェードインさせます。「1秒あたりどれだけ明るくなるか」—— この変化の速さこそ、微分で取り出せるものです。まず「一定の速さ(直線)」で、中2でやった y = ax の a をスライダーで動かしてみてください。それから他のフェードに切り替えると、 傾きが場所ごとに変わるのが見えます。

微分とは「グラフの各点での傾き」のこと。直線なら中2でやった a、曲線なら場所ごとに変わる a。それだけ。

★1 やさしい

P2 面積=積み重ねの合計 — カメラの露出

つかう数学: 長方形の面積 = 縦 × 横(小学校) / たし算

カメラの露出は「シャッターが開いている間に入ってきた光の合計」です。明るさが一定なら 明るさ × 時間 = 長方形の面積で計算できます。では撮影中に明るさが変わったら(ちらつくネオン、雲が流れる空)? ——細い長方形(短冊)に刻んで、全部足せばいい。短冊の本数を増やすと、合計が「本当の値」に近づいていきます。

積分とは「細かく刻んで全部足す」こと。長方形の面積計算を、形が曲がっていても使えるようにしただけ。カメラは毎ショットこれをやっている。

微分編 — 傾きを取り出す
★2

§1 トーンカーブの傾き=コントラスト — カラーグレーディング

つかう数学: P1の「グラフの各点での傾き」だけ

グレーディングでS字カーブを当てるとコントラストが上がり、シャドウを持ち上げると眠くなる——全部知っている現象です。 ではその「コントラスト」を数値で言うと何か? 答えはトーンカーブの傾き。 傾きが1より大きい明るさ帯はコントラストが増え、1より小さい帯は眠くなります。

コントラストとはトーンカーブの傾き(微分)のこと。グレーディングは「どの明るさに傾きを配るか」の設計。 白飛び・黒つぶれ = 傾き0で階調の差が消えること。

★2

§2 ハイトの傾き=法線 — ノーマルマップとシェーディング

つかう数学: P1の「傾き」+「面が光の方を向いているほど明るい」という日常感覚

ノーマルマップはなぜ平らなポリゴンに凹凸を見せられるのか。あの青紫のテクスチャの正体は、 ハイトマップの傾きから作った「面の向き(法線)」です。①の地形をドラッグすると、 ②傾き → ③陰影 が連動して変わります。「凹凸の強さ」スライダーは、いつも触っている ノーマルマップの Strength と同じもの——数学的には傾きに掛ける倍率です。

ノーマルマップは「傾き(微分)をテクスチャに焼いたもの」。画面の陰影は表面の微分で出来ている。

もっと知りたい人へ:明るさの計算の正体 「面が光の方を向いているほど明るい」は、法線と光の向きの角度で決まります。高校数学では この計算に「内積(ベクトルのかけ算)」という便利な道具が登場します。名前だけ覚えておくと、 シェーダのコードで dot(N, L) を見たとき「あれか」と分かります。
★2

§3 隣との差=エッジ — アウトライン抽出

つかう数学: 引き算だけ(P1の「傾き」が画像では「隣との差」になる)

トゥーン調のアウトラインは、深度バッファ(カメラからの距離を濃淡にした画像)で 隣のピクセルとの差が大きい場所を探すポストプロセスです。グラフの傾きは「隣の点との差 ÷ 間隔」でした。 画像は間隔が1ピクセルなだけ——つまりこれは画像の微分。ただの引き算です。 「差をとる方向」を横だけにすると、縦の輪郭しか出ないのも試してみてください。

輪郭線は画像の微分=隣のピクセルとの引き算。しきい値が「どこからを線とみなすか」の調整。

もっと知りたい人へ:GPUは微分だらけ GPUには ddx / ddy という「隣のピクセルとの差」を返す命令があり、 全ピクセルで毎フレーム実行されています。UV座標の差(=画面上でテクスチャがどれだけ縮んで見えるか)から ミップマップのレベルを選ぶのにも、この微分が使われています。
積分編 — 刻んで足し合わせる
★3

§4 重み付きで足す=ブラーとブルーム — ガウシアンブラー

つかう数学: P2の「刻んで足す」+ 割合(中1)

ブルームの根っこはブラー。ブラーは「周囲のピクセルを、近いほど大きい割合(重み)を付けて混ぜ合わせる」計算で、 P2の「刻んで足す」に重みが付いただけです。重みの合計は100%——だから明るさが保存されます。 タップ数(=P2の短冊の本数)を減らしてから半径を上げると、絵が壊れるのが分かります。 これが「タップ数をケチると画質が壊れる」の正体です。

ブラーもブルームも「重み付きで刻んで足す」=積分。タップ数は積分の短冊の本数で、削った分は誤差=アーティファクトになる。

★3

§5 ランダムに試して足す=ソフトシャドウ — エリアライトとモンテカルロ

つかう数学: P2の「刻んで足す」+ 割合(中1)。新しい考え方は「ランダムに試して割合で近似」

エリアライトの影の縁がふわっとするのは、地面の各点の明るさが「光源の面のうち、その点から見える割合」で 決まるからです。レンダラーはこれをランダムに何本か試して、届いた割合で近似します(モンテカルロ法)。 サンプル数を1本にしてから256本まで増やしてみてください——レイトレのノイズがサンプル不足の姿だと分かります。

影のやわらかさは積分の形。レンダラーのノイズは「まだ足し終わっていない積分」の姿。デノイザーが要る理由もここにある。

★3

§6 レイに沿って足す=ボリュームフォグ — レイマーチング

つかう数学: P2の「刻んで足す」+ 割合の掛け算(「1歩ごとに◯%ずつ減る」)

フォグやゴッドレイは、視線(レイ)に沿って霧の濃さを少しずつ確かめながら進むことで 「光がどれだけ残って届くか」を計算しています。1歩ごとに「残る光 × (1 − 濃さ)」を掛けていく—— お金の複利計算と同じ形です。ステップ数を4まで下げると縞(バンディング)が出ます。 それは刻みが粗すぎる積分の誤差が、そのまま絵に見えているものです。

フォグの1ピクセルはレイに沿った積分1本。画面全体では毎フレーム何十万本。バンディングは積分誤差が可視化されたもの。

もっと知りたい人へ:「毎歩◯%減」の行き着く先 「1歩ごとに◯%ずつ減る」の刻みを極限まで細かくしたものが、高校で習う指数関数(e)です。 フォグの透過率の式 T = exp(−∫σ) に出てくる exp がまさにそれ。読み方は 「視線上の濃さを全部足した量(∫σ)で、指数的に光が減る」。
挑戦編 — 描画システムは時間方向にも微積分する
★4 挑戦

§7 自動露出とフレーム蓄積 — 時間方向の微積分

つかう数学: これまでの全部(傾き・刻んで足す・割合)。新しい数学は出てきません

ここまでは画面の中(空間)の話でした。描画システムは時間方向にも微積分しています。 目の順応(自動露出)は「毎フレーム、目標との差の一定割合だけ近づく」計算。 このときΔt(1フレームの時間)を掛け忘れると、fpsによって順応の速さが変わるバグになります—— タブAでfpsを切り替えて、紫の線(掛け忘れ)だけが変わるのを確かめてください。 タブBでは、§5のノイズだらけの画像を毎フレーム混ぜて蓄積するとノイズが消えていきます。 TAAやパストレの蓄積と同じ、時間方向の積分です。

順応は時間方向の微分の応用、蓄積は時間方向の積分。動くとゴーストが出るのは「同じものを足し続ける」前提が崩れるから——TAAのゴーストの正体。

もっと知りたい人へ:この計算の名前 「差に比例して変化する」型の計算は、大学で微分方程式と呼ばれる道具の入口です。 ばね、慣性、露出の順応、カメラの追従——ゲームの「じわっと追いつく」動きは、ほぼ全部この形をしています。

総まとめ

微分 = 傾きを取り出す

  • コントラスト(トーンカーブの傾き)
  • 法線・ノーマルマップ(ハイトの傾き)
  • エッジ・輪郭線(隣のピクセルとの差)

積分 = 刻んで足す

  • 露出(明るさ × 時間の面積)
  • ブラー・ブルーム(重み付きの足し算)
  • ソフトシャドウ(見える割合の足し算)
  • フォグ(レイに沿った足し算)
  • フレーム蓄積(時間方向の足し算)

サンプル数 = 刻みの細かさ

  • ブラーのタップ数
  • シャドウのサンプル数
  • レイマーチのステップ数
  • 削るほど誤差(ノイズ・縞・欠け)が出る。品質とパフォーマンスの取引の正体は積分誤差

各セクションの学び

  1. P1 微分とは「グラフの各点での傾き」。直線なら中2の a。
  2. P2 積分とは「細かく刻んで全部足す」。長方形の面積の延長。
  3. §1 コントラストとはトーンカーブの傾きのこと。
  4. §2 ノーマルマップは傾きをテクスチャに焼いたもの。
  5. §3 輪郭線は画像の微分=隣のピクセルとの引き算。
  6. §4 ブラーは重み付きの積分。タップ数は短冊の本数。
  7. §5 レンダラーのノイズは「まだ足し終わっていない積分」。
  8. §6 バンディングは積分誤差が絵になったもの。
  9. §7 レンダリングは空間でも時間でも微積分している。

用語ミニ辞典

微分
グラフの各点での傾き(変化の速さ)を求めること。
積分
細かく刻んで全部足すこと。曲がった形でも「合計」が出せる。
傾き
横に1進んだとき縦にいくつ変わるか。中2の一次関数の a。
法線
面に垂直な向き。面の傾きから作る。ライティングの基本材料。
重み
足すときに掛ける割合。ブラーでは「近いほど大きい割合」。
サンプル
積分を近似するための「試し撃ち」1回分。多いほど正確で、重い。
モンテカルロ法
ランダムに試して割合で答えを近似する方法。パストレーサーの心臓部。
レイマーチング
レイに沿って1歩ずつ進みながら足していく数値積分。フォグや雲の描画に使う。
ddx / ddy
GPUの「隣のピクセルとの差」命令。画像の微分。ミップ選択にも使われる。
Δt(デルタティー)
1フレームの経過時間。掛け忘れるとfps依存のバグになる。
